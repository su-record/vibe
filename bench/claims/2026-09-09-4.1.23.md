# Pre-registered claim — 4.1.23, the fair bench, 2026-09-09

Written before the bench runs; not adjusted after seeing the data. This is the first run in which the `on` arm cannot read the key: each task is split into `checks/` (copied to both arms), `key/` (the reference answer, the expected output, the fake user — reaches the workspace only at judge time) and `judge/` (an intent with no key in it), proved by `checks/bench-no-key.js` and the key-value grep in `checks/bench-judge.js`. Both arms get identical files; the `on` arm adds `.vibe/` with the intent and scenarios, the card, the skills and the hook. Also new since the fifth run: results bound to the tree, approval re-verified at check, parents judged by this run, every command segment gated; queries never repair the install. Arms: claude × {on, off}, codex × {on, off}; five runs per arm per task; `--parallel 3`; both arms isolated.

- Overhead set (settlement, vibe-fix, report): `on` checks not worse; `on` weighted input tokens ≤ `off` × 1.25; `on` ms ≤ `off` × 1.5 — per client, means over five runs. Turns reported.
- Direction set: `ask` — per client, `on` scores higher on checks than `off`; `session-split` — per client, `on` checks not worse and `on` weighted tokens over the two sessions ≤ `off`.
- Context set (brownfield): `on` weighted tokens ≤ `off` × 0.7 per client.
- The gate is a release condition (`gate-is-release` in the intent): the release ships only if every rule passes; otherwise README says which rule fails and the release waits. Whatever falls: the numbers are reported as measured, and every earlier `on`-arm number stays withdrawn.

## During the run — Codex out of credit
At 08:5x the Codex account hit its usage limit ("You've hit your usage limit … try again at Sep 15th, 2026"): every codex `off` run and the codex `on` brownfield runs ended in seconds with nothing done. Those 24 lines are annotated `error` in the ledger and the gate never counts a line with an error; the arm was stopped. Codex `on` settlement, vibe-fix, report, ask and session-split ran before the limit and stand, but without an `off` arm they compare to nothing. This release measures Claude Code; Codex is unmeasured until the account can run again, and README says so. `bench/run.js` now names a client's limit or capacity error on the line and stops the arm on it.
