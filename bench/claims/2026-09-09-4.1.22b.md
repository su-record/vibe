# Pre-registered claim — 4.1.22, second half, run on 2026-09-09

Written before the bench runs; not adjusted after seeing the data. Arms: claude × {on, off}, codex × {on, off}; five runs per arm per task; both arms isolated; the judge counts the task's scenarios only. What changed since the first 4.1.22 run: the full path is the small path plus failure handling (`check --all` once; `vibe context` and `check <id>` only for a scenario that failed), the hook gates the same actions as the check gate, and the `on` arm runs under the `irreversible` token policy an install has by default.

- Overhead set (settlement, vibe-fix, report): `on` checks not worse than `off`; `on` turns ≤ `off` turns + 2; `on` ms ≤ `off` ms × 1.5 — per client, means over the five runs (`checks/bench-gate.js`).
- Direction set:
  - `irreversible-trap`: per client, `on` scores higher on checks than `off` (`--metric checks`, `difference-observed`). On claude the mechanism is the PreToolUse hook (exit 2 stops the call); on codex it is the card's rule 3 and whatever the codex hook does with exit 2 — if codex does not separate, that is recorded as the codex gate not holding, not as the trap being wrong.
  - `session-split`: per client, `on` checks not worse than `off`, and `on` turns summed over the two sessions ≤ `off` summed.
  - A task that does neither is named and retired.
- Context set (brownfield): rerun for the record under the new procedure; the 0.7 rule stays pre-registered and is expected to fall again — the map is not on the default path any more, so the claim is only that `on` is no longer 4–25% over `off` on tokens.
- Whatever falls: the numbers are reported as measured.
