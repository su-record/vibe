# Fieldwork in the personal FDE

A successful implementation may still fail in the user's actual workflow. Vibe now routes recurring-workflow discovery, user corrections, real-use failures and repeated workarounds to an internal fieldwork guide. It connects observed operating meanings, preservation of existing user abilities, target-environment evidence and justified reuse to the existing knowledge and extension mechanisms.

The brief prioritizes optional `corrections.md`, `work-context.md` and `reuse.md` within each existing project/personal knowledge directory. Each directory still contributes at most twenty file paths. It does not automatically load note bodies, write records, infer corrections, index projects or call a model. Other notes remain available through ordinary file access. Directories masquerading as Markdown files and symlink entries are not listed as notes.

The guide asks the agent to apply a correction before retaining it, distinguish project facts from confirmed personal preferences, and preserve the source, scope and current uncertainty. It does not turn saved notes into execution authority. Real-use observations remain separate from tests and user acceptance. Recurring fixes are candidates for existing extensions or reusable code only when reuse and maintenance are justified; temporary workarounds need an exit condition.

Validation covers a knowledge directory with more than twenty alphabetically earlier notes: relevant context stays discoverable, no bodies are automatically loaded, and no files are changed by reading the brief. Existing guide delivery and package checks cover CLI/MCP access and one public entry. These checks do not prove that a model correctly interprets a correction or understands an undocumented workflow.

Representative real-use cases are a Windows-only incident after Linux test success, a format migration that removes a user's inspection method, a user correction that must change the next task, and a repeated workaround that should either become reusable or be retired. Evaluate actual behavior and source evidence when those tasks occur; no per-task evaluation pipeline or extra reviewer is introduced.
