# Code Slop Catalogue

One row per marker. "Strength" follows the skill's tiers: a strong marker is
enough on its own; a weak marker only counts when two or more overlap in the
same function or file. Do not run this as a list of banned constructs — each
alternative names what to decide instead, not a substitute default. Patterns
are illustrative greps across common languages, not exhaustive regexes.

| Marker | What it looks like | A pattern a reviewer can grep | Strength | Fix |
|---|---|---|---|---|
| Comment restates the line | A comment whose words are the same words as the code beneath it | A `#`/`//` comment line immediately followed by a line whose identifiers and verb match it, e.g. `# increment the counter` above `counter += 1` | Weak | Delete the comment; if it explains why, keep only the why. |
| Docstring on a getter | A method docstring that says only what the method's name already says | `def get_\w+\(self\):\s*\n\s*"""Gets` or `"""Returns the \w+\."""` above a one-line return | Weak | Delete the docstring, or replace it with the one fact the name does not carry (units, a side effect, a caveat). |
| Guard for an impossible state | A null/type check or `assert` on a value the call graph never actually produces | `if \w+ is None:\s*raise` or `assert \w+ is not None` with no caller that can pass `None` | Weak | Remove the guard, or replace it with a real invariant the type system does not already enforce. |
| Try/except or try/catch that swallows | A failure disappears instead of propagating or being handled | `except:\s*pass`, `except Exception:\s*pass`, `catch\s*\(\w*\)\s*\{\s*\}` | Strong | Let the exception propagate, or handle it with a specific catch and a real recovery or log line naming the failure. |
| Interface or abstract class with one implementation | A substitution point built for a swap that never happens | `interface \w+` with exactly one `implements` of it in the codebase, or `class \w+\(ABC\)` with exactly one concrete subclass | Strong | Delete the interface and call the one implementation directly; reintroduce it when a second implementation actually exists. |
| Factory for one class | A creation function that only ever returns one type | `def create_\w+\(` or `class \w+Factory\b` returning a single concrete type with no branching | Weak | Replace the factory call with the constructor directly. |
| Manager/Helper/Utils/Handler/Service names with nothing behind them | A class named for a role, holding an unrelated grab-bag of methods | `class \w+(Manager\|Helper\|Utils\|Handler\|Service)\b` | Weak | Name the class for what it actually holds or does; split unrelated methods into their own homes. |
| Wrapper that only forwards | A function whose body only calls another function with the same arguments | `def \w+\(([^)]*)\):\s*\n\s*return \w+\(\1\)` or `return await inner\(` with identical arguments | Weak | Call the wrapped function directly at each call site; delete the wrapper. |
| Constant made configurable that never varies | A config or environment lookup for a key with exactly one value everywhere it is set | `config\.get\("[A-Z_]+"` or `os\.environ\.get\("[A-Z_]+"` whose key has one value across every config file in the repo | Weak | Replace it with a plain named constant in code. |
| Dead code, kept "just in case" or commented out | A branch nothing reaches, or old code left next to its replacement | A block of `#`/`//` commented-out statements, or a function/branch with no caller found by search | Strong | Delete it; version control already has the history. |
| "Robust"/"enhanced"/"improved"/"comprehensive" naming | A quality claim in place of a specific description | `\b(robust\|enhanced\|improved\|comprehensive)\b` in an identifier, a comment, or a commit message | Strong | Name the specific behaviour or fix instead of the adjective. |
| TODO/FIXME that ships | A marker for work that was never done, left in shipped code | `#\s*TODO`, `//\s*TODO`, `FIXME` with no linked issue | Strong | Do the work, file a tracked issue and reference it, or delete the marker. |
| Logging every step | A log or print call after nearly every line, burying the line that matters | Multiple `print\(` or `log(ger)?\.(info\|debug)\(` calls per function body, one per statement | Weak | Keep only the log line that marks a real state change or failure. |
| Generic error message | An error with no failing operation named and no next step | `raise Exception\("Something went wrong"\)`, `throw new Error\("failed"\)` | Strong | Name what failed and what to do: the operation, the input, and the fix. |
| Type/annotation noise repeating the obvious | An annotation or trailing comment that restates the type or the name | `\w+: int\s*#\s*(an? )?int(eger)?\b` or a return type annotation matching the function's own name with no added information | Weak | Delete the noise; keep only an annotation that adds information a reader could not infer. |
| Re-exports and barrels nobody imports | An index file re-exporting a directory that nothing imports through it | `export \* from` in `index.ts`, or `__all__ = \[.*\]` in `__init__.py`, with no import found elsewhere using that path | Weak | Delete the barrel; import from the concrete module directly. |
| Test asserts the implementation, not behaviour | A test checks that an internal method ran, not what the code produced | `assert_called_with\(`, `toHaveBeenCalledTimes\(`, `\.mock\.calls\.length` with no assertion on a return value or observable state in the same test | Strong | Rewrite the assertion against the function's return value or the system's observable state. |
| Commit message that praises itself | A self-assessment in place of a description of the change | `[Ss]uccessfully (implemented\|added\|fixed)`, `now works perfectly`, `fully functional` in a commit message | Strong | State what changed and why, not how well it turned out. |
