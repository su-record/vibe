# vibe 4 · 4.1.10 — the harness reads for the model: `vibe read --ask` hands a file corpus to a low-reasoning model

## Why
Most of a coding session's tokens go to reading, not reasoning: the frontier model loads whole files into its context to answer "what does this module do", "where is X handled", "what does this report say". Spotify's shunt plugin measured a ~90% mean token cut on bulk reads by routing them to a cheap worker model whose reply — not the files — enters the main context. Its limits are documented: the worker's summaries carry no line numbers, so edits and debugging still need the real file.

vibe already has the two pieces: `vibe read` extracts text from any document with no dependency, and the `review` check already spawns the client CLI (`claude -p`, `codex exec`) with a prompt on stdin. Joining them gives every client the same delegation without a hook that blocks reads: the harness reads, numbers the lines, asks a low-reasoning model, and returns only the answer. Card rule 8 ("read files whole") stays for editing and debugging; the new rule says when not to.

Reading is only cheap when the corpus is sent once. Measured on this machine with Haiku: a 37,576-character bundle costs 13,132 cache-creation tokens and $0.044 the first time; a follow-up question in the same session reads those 13,132 tokens from cache, writes 903, and costs $0.0053 in half the time. Without a session every question pays the first price again. And a bare `claude -p` run inside a project drags the whole harness context along — 16,311 tokens of card, CLAUDE.md, plugins and hooks before the first file — where a reader with its own system prompt, no tools and no settings starts at 428. So the harness manages the cache: one reader session per file set, resumed for follow-ups, reported so the caller sees the hit.

## What counts as success
- `vibe read <file…> --ask "<question>"` extracts every named file (documents through the existing readers, code and text verbatim), numbers the lines of text and code files (`N| line`) so the answer can cite them, wraps each file in `<file path="…">…</file>`, and sends the bundle to the reader with the question last. The reply is printed; stderr reports files, chars, reader, session (new or resumed), cache tokens read and written, and time; `--json` carries `{ files, chars, reader, session: { id, resumed }, usage: { input, cacheRead, cacheWrite, output }, reply, ms }`.
- `vibe read <file…>` without `--ask` accepts several files and prints them one after another, as before for one.
- The reader is chosen in order: `VIBE_READER_CMD` (a stateless command, bundle on stdin, answer on stdout — no session), `reader` in `.vibe/config.json` (same), `claude` on PATH, `codex` on PATH; with none the command fails with exit 2 naming the four options.
- The Claude reader runs `claude -p --output-format json --model haiku` with the reader instructions as `--system-prompt`, `--tools ""`, `--disable-slash-commands`, `--strict-mcp-config`, `--setting-sources ""`, in a neutral working directory (`~/.config/vibe/reader`), so no project card, memory, plugin or hook enters the reader's context; `CLAUDECODE` is removed from its environment. The Codex reader runs `codex exec --skip-git-repo-check --json -c model_reasoning_effort=low -` in the same neutral directory. Session id and token usage are read from each CLI's JSON.
- Sessions are managed by the harness: the key is a hash of the reader and the exact bundle text; `~/.config/vibe/reader/sessions.json` maps key → `{ id, client, at, files, chars }`. A second `--ask` over the same files within one hour resumes that session (`claude -p --resume <id>` · `codex exec --skip-git-repo-check resume <id> --json …`) and sends only the question, so the corpus is read from cache; a changed file, a different file set or an expired entry starts a new session. Entries older than one hour are dropped when the index is written.
- The bundle is capped at 400,000 characters; over the cap the command fails with exit 2 and tells the caller to ask about fewer files or use `--pages` / `--sheet`. The reader has 300 s.
- The `review` check's Codex command gains `--skip-git-repo-check`, so a manuscript outside a git repository can be reviewed; nothing else in `review` changes.
- The notification hook gains a `PreToolUse` entry for `Read`: inside a vibe project, when the file being read is over 400 lines, it adds context naming the line count and `vibe read <file> --ask "…"`. It never blocks; outside a project it is silent; both plugin manifests (`hooks/hooks.json`, `hooks/codex-hooks.json`) and the home-settings install carry the entry.
- Card rule 8 says when to delegate: a file that only has to be understood, not edited or debugged, goes through `vibe read --ask`. The card stays ≤ 1KB. `vibe-build` and `vibe-discover` name the same rule in one line each; the six common skills stay ≤ 300 lines.
- Tests: a fake stateless reader (`VIBE_READER_CMD`) proves the bundle shape (file tags, numbered lines, question last, several files), the reply passthrough, the cap, and the exit-2 error without a reader; a fake `claude` on PATH proves the Claude driver's flags, the JSON parse, that the second ask over the same files resumes the session with only the question, that a changed file starts a new session, and that an entry older than an hour is not resumed; a fake `codex` proves the Codex driver and resume the same way; the hook test proves the advice for a long file and silence for a short one.
- Live proof: with `claude` on this machine, two `vibe read src/core/skills.ts src/core/regress.ts --ask …` in a row — the first answers, the second reports `resumed` with cache-read tokens above zero.
- Earlier gates still hold: build, tests, card ≤ 1KB, file 400 / function 50, six common skills ≤ 300 lines, language packs within budget, plugin tree current for 4.1.10, README status line carries `4.1.10`, help lists `--ask`.

## Constraints
- No new dependency. The worker is whichever client CLI is already installed; nothing is downloaded.
- The hook advises; it never blocks a read. Card rule 8 (read whole for editing and debugging) is not weakened.
- `review` check behaviour does not change beyond the Codex `--skip-git-repo-check` flag.
- Every record is English; the model talks to the user in the user's language.
